# API Contracts

This document describes the REST API contract (v1.1). During scaffolding, create routes and schemas but do not implement the scientific calculations or the route-finding engine. Each endpoint lists its **initial scaffold behavior**; once an endpoint is implemented, update this document in the same Pull Request.

- **Base prefix:** `/api/v1`
- **Format:** JSON UTF-8, `snake_case` field names.
- **Interactive docs:** `/docs` (generated by FastAPI; it must match this document).

## Architecture notes

- The backend is Python (FastAPI). Route planning (A*) runs on the backend over a pre-built **cost stack** (see "Data contract").
- Heavy rasters live in a **static data store** (S3 or any static host), not in Git. The backend refreshes its local cache in a background task during startup; route requests read only the raster window they need.
- **No database in v1.** Saved routes are kept in memory (max ~100, oldest evicted). `app/database/` and `app/models/` are kept but not imported from `main.py`.
- **Image tiles** (HiRISE, CTX, THEMIS…) are requested by the frontend directly from NASA Trek or the data store. Do not add a tile-server endpoint unless the team explicitly chooses to implement it.

## Endpoints

| Method | Endpoint | Purpose | Initial scaffold behavior |
|---|---|---|---|
| GET | `/health` | Check API availability and per-dataset status | Return application status; unavailable datasets marked `unavailable` |
| GET | `/site` | Study area, master grid and science stops | Return 501 until the DEM and grid are prepared |
| GET | `/mars/layers` | List known data layers | Return configured layer metadata; unavailable layers must be marked unavailable |
| GET | `/mars/terrain` | Query all terrain measurements at a coordinate | Return 501 until implemented |
| GET | `/mars/traverse/curiosity` | Curiosity traverse clipped to the study area | Return 501 until implemented |
| GET | `/mars/images/near` | Curiosity raw images near a coordinate | Return 501 until implemented |
| GET | `/mars/layers/{layer_id}/raster` | Retrieve a backend-generated raster visualization | Return 404 if the requested generated file does not exist |
| POST | `/routes/plan` | Request a route | Calculate a pedestrian route over the slope raster. Returns 200 with route geometry, metrics, and rest stops, or an error code (see "Route response shape" and error code table). |
| GET | `/routes/{route_id}` | Retrieve a calculated route (in memory) | Return 404 when no such route exists |

Removed from the previous version: `/mars/texture`, `/mars/elevation` (merged into `/mars/terrain`) and `/mars/layers/{layer_id}/data`.

The initial layer-list response includes the planned categories described in the project overview, each marked unavailable. Unknown source, unit, resolution and coordinate-reference metadata is `null`; these entries do not assert that a dataset has been obtained or validated.

## Coordinate conventions

| Concept | Rule |
|---|---|
| Body and datum | Mars 2000 (IAU) |
| Latitude | Decimal degrees, **planetocentric**, `[-90, 90]` |
| Longitude | Decimal degrees, **positive east**, `[-180, 180]`. If a source uses `0–360`, normalize it **when reading it** |
| Elevation | Meters above the **areoid** |
| Internal projection | Free (the DEM's native CRS). The API only exposes latitude/longitude; the backend converts with `pyproj` |

Request objects use named fields:

```json
{
  "latitude": -4.5,
  "longitude": 137.4
}
```

GeoJSON geometry coordinates use `[longitude, latitude]` or `[longitude, latitude, elevation_m]` (RFC 7946):

```json
[137.4, -4.5]
```

Coordinate values in examples are illustrative only.

**Why this matters:** at Mount Sharp's latitude, mixing planetocentric and planetographic latitude shifts points by about 3.26 km.

**Acceptance test:** points returned by `GET /mars/traverse/curiosity` must fall on the rover tracks visible in the HiRISE layer, with an error under 10 m. Apply the same test to every new layer.

## Units

Every field name carries its unit as a suffix: `_m` meters, `_min` minutes, `_deg` degrees, `_mgy` milligray, `_ms` milliseconds. Distances are **always in meters** (`distance_m`, never `distance_km`).

## Data honesty rules

- Never fabricate measurements, distances, route geometry or data availability.
- If there is no valid data, the field is `null` and its availability says so.
- Anything modeled or estimated (radiation, values decoded from color tiles) is marked `"estimated"` and carries a `model` or `source` field.
- If a layer is unavailable, route planning runs **without it** and declares it in `data_quality` and `computation.layers_unavailable`.
- Do not return `status: "completed"` with fabricated route data.

## Health response shape

```json
{
  "status": "ok",
  "api_version": "1.1.0",
  "datasets": {
    "slope_raster": "available",
    "science_stops": "available",
    "curiosity_traverse": "available"
  },
  "layers": {
    "elevation_m": "available",
    "slope_deg": "available",
    "roughness_m": "available",
    "radiation_mgy_day": "estimated",
    "thermal_inertia": "unavailable"
  },
  "database_status": "disabled"
}
```

- `status`: `"ok"` or `"degraded"`. If the configured slope raster is missing or invalid, return `degraded` with HTTP 503.
- `datasets.*`: `"available"` | `"unavailable"`.
- `layers.*`: `"available"` | `"partial"` | `"estimated"` | `"unavailable"` (taken from the layer registry).

## Layer metadata shape

```json
{
  "layer_id": "slope_deg",
  "name": "Computed slope",
  "description": "Slope derived from the HiRISE DEM.",
  "category": "derived",
  "role": "cost",
  "quality": "available",
  "available": true,
  "source": "Own computation from the DEM",
  "units": "deg",
  "spatial_resolution": "5 m",
  "coordinate_reference_system": "Mars 2000",
  "tile_url": null,
  "raster_url": "/api/v1/mars/layers/slope_deg/raster",
  "tiling_scheme": null,
  "bbox": [137.30, -4.90, 137.50, -4.60],
  "max_level": null,
  "default_opacity": 0.6,
  "legend": { "type": "ramp", "unit": "deg", "stops": [[0, "#2bb3c0"], [15, "#e6dc4a"], [30, "#c8423a"]] }
}
```

- `category`: `optical | topographic | thermal | spectral | geologic | radiation | derived`.
- `role`: `display` (shown only) or `cost` (used by the route planner).
- `quality`: `available | partial | estimated | unavailable`. `available` (boolean) is `true` unless `quality` is `unavailable`.
- A layer uses **either** `tile_url` (tiles) **or** `raster_url` (single PNG from the backend), never both.
- `GET /mars/layers` is generated from `layers_registry.yaml`, so the catalog and the cost calculation never drift apart.

## Route request

```json
{
  "origin": { "latitude": -4.8149309421, "longitude": 137.3720378680 },
  "destination": { "latitude": -4.8221853022, "longitude": 137.3634338595 },
  "max_km": 5.0,
  "descanso_min": 10,
  "velocidad_ms": 0.7,
  "pendiente_max_deg": 12
}
```

| Field | Type | Required | Default | Notes |
|---|---|---|---|---|
| `origin`, `destination` | `{latitude, longitude}` | yes | — | |
| `max_km` | float `(0, 10]` | no | 5.0 | Maximum route length and direct-distance limit |
| `descanso_min` | float > 0 | no | 10 | Rest duration at each suggested stop |
| `velocidad_ms` | float `(0, 1.0]` | no | 0.7 | Nominal walking speed for a suited human |
| `pendiente_max_deg` | float `(0, 20]` | no | 12 | Steeper cells are impassable |

This endpoint models **one suited human walking**, not a rover. `max_km` limits
route length; it is distinct from the GeoTIFF's geographic coverage radius.
Walking speed reduction with slope and rest duration are modeling assumptions,
not validated Mars EVA measurements.

    "Modelo: persona caminando con traje espacial, no rover.",

Rules:

- `puntos` contains `[longitude, latitude]` coordinates in route order.
- Rest stops are suggestions on the calculated path and do not alter its geometry.
- A stop is selected at the minimum slope between 1.0 and 1.5 km from the previous stop or origin; the destination is never a stop.
- `horas_caminando` uses `v = velocidad_ms * max(0.2, 1 - pendiente_local / 20)` at each step.
- `tiempo_descanso_h` is the number of stops multiplied by `descanso_min / 60`.
- `referencia_neutrones.zonas` reports the AND product's thermal and epithermal neutron count rates for every 5° × 5° cell touched by the route, with reported spread and descriptive comparison to available neighboring cells.
- The AND product is a coarse regional neutron reference, not a human radiation dose; it is not included in the A* cost.
- The example is illustrative; the returned route values are computed from the selected raster.

`warnings[].code` values:

| `code` | When | `severity` |
|---|---|---|
| `STEEP_SLOPE` | Stretch with slope ≥ 80 % of `max_slope_deg` | `warning` |
| `ROUGH_TERRAIN` | High roughness (rocks, broken terrain) | `warning` |
| `LOOSE_TERRAIN` | Low thermal inertia (loose sand) | `warning` |
| `RADIATION_EXPOSURE` | Estimated dose above threshold | `warning` / `critical` |
| `TIME_BUDGET` | Total time ≥ 80 % of `max_duration_min` (≥ 95 % = `critical`) | `warning` / `critical` |
| `FAR_FROM_ORIGIN` | Point far from base (hard to return) | `info` / `warning` |
| `DATA_GAP` | Stretch without valid data | `warning` |

Infeasible route error:

```json
{
  "code": "NO_FEASIBLE_ROUTE",
  "message": "No route exists with slopes ≤ 15°. The minimum possible needs 19.2°.",
  "details": { "blocking_constraint": "max_slope_deg", "min_required": 19.2 }
}
```
